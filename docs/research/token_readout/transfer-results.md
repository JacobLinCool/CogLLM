# Token-level readouts across backbones

Frozen Qwen3.5-2B, LFM3-1.7B-Base, and Gemma 4 E2B each processed the same 191 texts in one causal forward pass per text on Colab L4. After fitting on the same endpoints, Qwen's span readout achieved the lowest held-out NLL on full-document Frick first reports and ExpMRC evidence intervals. With IIRC supervision and calibration, the Qwen readout improved correct localization of both early and late resolution for a single issue from 1/12 to 6/12, below the prespecified threshold of 9/12. In the eight two-issue controls, no variant correctly selected and localized both issues. ## Held-out results

Each backbone in the table uses a span readout with development-set calibration. Frick NLL measures the full-document first-report likelihood weighted across 384 human trials, with a position baseline of 1.785 nats per trial. ExpMRC NLL measures the likelihood of a human-annotated interval across 27 articles, with the original questions supplied to each model. Its position-only baseline ranges from 3.041 to 3.044 nats per question according to each tokenizer's exposure counts. Lower NLL is better for both endpoints.

In the uncalibrated comparison within Qwen, the span readout lowered first-report NLL from 1.372 to 1.295 and evidence NLL from 2.849 to 2.680. LFM3's span readout lowered first-report NLL from 1.461 to 1.438, and its evidence NLL rose from 2.961 to 3.068. The Gemma span readout lowered uncalibrated evidence NLL from 3.676 to 3.256, which fell to 2.921 after calibration. Gemma's calibrated readout ranked 19/27 pairs correctly. Always selecting the first question yielded 17/27, and the calibrated readout scored 60.0% under equal weighting of the two question-order strata. All three backbones underestimated the human target-sentence effect. [Endpoints and paired intervals](../../../research/results/portable-token-readout-l4/metrics.json)

Adding IIRC and development-set calibration correctly localized both early and late cues in five more families than the same backbone at the same calibration stage. The difference was +41.7 percentage points, with a paired bootstrap interval of [+16.7, +66.7] percentage points across the 12 families. This describes the authored controls. The ExpMRC NLL difference was +0.029 nats per question, with an interval of [−0.158, +0.225]. The equally weighted difference across the four Frick families was close to zero. The IIRC point readout passed the individual check for 1 of 16 A/B cues. No readout passed both directions of a two-issue family. The A/B evaluation supplies both candidate anchors. Finding issues in the text unaided and tracking the same issue through resolution remain unverified. Before linking the formal test annotations, we selected Qwen's span readout with IIRC and calibration using the equally weighted development mean. The mean fell from 1.811 nats without IIRC to 1.785. This selection follows the development objective, and the best held-out candidate varies by endpoint. [Selection receipt](../../../research/results/portable-token-readout-l4/candidate.json)

## Implementation and data

The shared readout receives each token's intermediate and final hidden states and character span. When enabled, it also receives summaries of native global attention. Each native global attention layer contributes attention over the full visible prefix using the model's original mask and scaling. The summaries aggregate the mean and peak across heads and layers. LFM3's convolution and sliding-window layers and Gemma's sliding-window layers run as in the original backbone and contribute through its hidden states. The span variant forms a candidate from up to four tokens ending at the anchor and matches it to any later position. We fit a separate readout for each frozen backbone, adding about 203,000–213,000 trainable parameters. [Extractor](../../../research/token_readout/backbone.py) · [Readout](../../../research/token_readout/readout.py)

The shared packet retains 167 existing texts and adds 24 controls in 8 two-issue families. Frick uses 12/4/4 training, development, and test families. ExpMRC uses 48/16/27 articles. We align the three tokenizers at common character stops or intervals in the original text. Only existing whitespace falls between the 584 adjusted Frick stops and their original locations, so the model has yet to see the next sentence at each stop. All original data are retained. The two-issue test holds both candidate anchors fixed and gives the model only the body text. We keep the original 12 early-cue, late-cue, and no-cue controls. Neither engineering diagnostic adds human observations. [Fixed protocol](transfer-protocol.md) · [Dataset seal](../../../research/results/portable-token-readout-l4/qwen/dataset-receipt.json)

Equally weighted development NLL on Frick and ExpMRC determines stopping, checkpoint selection, and the backbone for the IIRC experiment. We fit the point and span readouts on the same data. The calibrated span readout fits post hoc logit gains for opening and resolution and a resolution bias on the development split. In ExpMRC, the question displayed first had evidence earlier in 17 of the 27 articles. We therefore report both the 63.0% first-question baseline and an equally weighted result across question-order strata. [Calibration and fitting](../../../research/token_readout/transfer_fit.py) · [Character-aligned scoring](../../../research/token_readout/transfer_score.py)

The Qwen follow-up adds 160 passages from the official IIRC training split. Each has a unique upstream anchor and a subsequent annotated support span in the same passage. The model reads the original passage without an inserted question. The auxiliary interval loss has weight 0.5. The two original endpoints retain 48 updates per epoch each. The additional material shares no exact contiguous twelve-word windows with the original 191 texts. Three potential within-source pairs with two anchors failed the uniqueness or token-boundary check. The supplemental packet therefore has 160 single-anchor intervals and zero two-anchor pairs. Annotators identified the support intervals after reading. ## Execution verification

All three backbones passed truncation and suffix replacement checks for native prefix extraction. Gemma's initial run failed the absolute hidden-state difference check after truncation. Retesting used the earlier cross-backbone experiment's 0.001 limit for relative RMS difference per token, with a maximum observed value of 0.000615. The native attention summaries retained an absolute difference limit of 0.001 and reached at most 0.000754. The retest used the original snapshot and extraction computation. Point and span readouts in all four fitting sessions met the prespecified development stopping criterion at epoch 10. Both final scores reproduced bit for bit. [Gemma retest](../../../research/results/portable-token-readout-l4/gemma-gate-recovery.json) · [Example development stopping receipt](../../../research/results/portable-token-readout-l4/linked/fitting.json)

The selected checkpoint passed three actual Gradio HTTP requests covering 90 tokens and 360 curve points, with three backbone forward passes. Six interface selections reused the extracted features. Across the four curves at the 25 common prefix tokens, the maximum absolute difference was 4.48×10⁻⁸, and every earlier-text reference stayed unchanged. The three baseline experiments, IIRC follow-up, interface validation, and initial Gemma session were all released. ## Reproduction and analysis interface

Start the interface using the checkpoint path in the [candidate receipt](../../../research/results/portable-token-readout-l4/candidate.json) and its [pinned model snapshot](../../../research/backbone_transfer/models.json). The interface reads the backbone, readout type, and calibration from the checkpoint and verifies the loaded backbone revision. The pinned execution environment uses Colab L4.

```sh
python -m research.token_readout.app \
  --runner research.token_readout.portable_runner:load \
  --model /path/to/pinned-model-snapshot \
  --checkpoint /path/from/candidate.json
```

The entry points for cross-backbone data preparation, training, and scoring are `research.token_readout.transfer_data`, `research.token_readout.transfer_colab`, and `research.token_readout.transfer_score`. Rebuild the supplemental material with `research.token_readout.linked_supplement` and seal its run separately with `transfer_colab prepare --experiment linked`. Each run directory retains per-epoch losses, checkpoints, formal forecasts, prefix checks, and release receipts.
