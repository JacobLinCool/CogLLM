# IIRC linked-evidence preparation and verification

This experiment tests whether a known query anchor can aid in locating the selected evidence within linked articles. The asker first reads the original passage and identifies the link. the responder subsequently accesses the linked article and marks the supporting text. The measurable endpoint is the reading stop at which the fully marked evidence first appears. The two tasks were completed by different participants, and the time taken by the original asker to resolve the query was not recorded. [IIRC §§2.2–2.3](https://aclanthology.org/2020.emnlp-main.86.pdf#page=4)

## Material and Reasoning Input

Retain only the single uniquely locatable link in the original passage. This link corresponds to a single question authored by one author, where the respondent submitted an answer and marked an external evidence segment precisely alignable with the same linked article. Coordinates are taken from `context.indices` and manually verified against the author's original text with HTML tags removed. Non-answered, unsupported by external evidence, multiple segments, and alignment failures are each counted separately. [Author Article Parser](https://github.com/jferguson144/IIRC-baseline/blob/main/util.py#L35-L44) · [Input Builder](../../research/semantic_tracking/iirc_linked_prepare.py)

Construct a path using the original passage, two line breaks, and the first 8,000 Unicode characters from the linked article, processed in a single causal forward pass. Provided anchor spans, linked text start points, and causal reading stops within the original passage serve as model-available localization information. Establish a nominal reading stop every 128 characters from the linked start point, then backtrack to boundaries amenable to independent re-tokenization verification. Align the end and anchor sentence-internal endpoints. All reading stops are constructed solely from the input text and provided anchor spans. The original query string, answer, support span, and linked title are retained outside the inference data. [Input Construction Program](../../research/semantic_tracking/iirc_linked_prepare.py)

The official dev set is used for held-out evaluation. Training data excludes cases where the original or linked article identifiers intersect with dev original segments or visible links. Statistical resampling groups are formed by linking original and linked article names with source text hashes. The training set retains 3,354 paths, yielding 3,174 observed intervals and 180 right-censored intervals from 2,352 article groups. The held-out set retains 452 paths, yielding 413 observed intervals and 39 right-censored intervals from 269 article groups. There is no overlap in article names or exact source text hashes between the split and source verification sets. [Split and Source Audit](../../research/results/iirc-linked-prepare-audit.json)

## Metrics and Acceptance Thresholds

Let \(T\) denote the first link body reading stop that reads all labeled evidence, indexed starting from 1. If the evidence end exceeds the final reading stop, the case is right-censored at the final reading stop \(L\). Censoring includes cases where only part of the evidence has been read. Observed events are counted as \(-\log P(T=t)\), and censored events as \(-\log P(T>L)\). Negative log-likelihood is measured in nats, with equal weighting across each question. lower is better. Additionally, the Brier score for each question is computed as the mean squared error of the cumulative event probability at its own link reading stop, with equal weighting across each question. The Brier score ranges from 0 to 1, with lower values indicating better performance.

The same data, split, event objective, learning objective, and evaluation reading stop utilize three types of readouts. The position baseline incorporates position features including visible character length, anchor span, and the current reading stop width. The second baseline adds the causal state of the linked body text along the same path, omitting explicit anchor vectors. The candidate readout further includes the interaction between the given anchor state and the linked reading stop state. Features used for each reading stop are limited to the text and position already presented at that time, with cumulative probability derived from the product of event probabilities at each step.

Evaluate the prespecified criteria using two-sided 95% intervals from 10,000 grouped paired bootstrap replicates. For candidate minus position baseline, the upper bound of the mean negative log likelihood difference must be at most −0.02 nats, and the upper bound of the Brier difference must be at most +0.01. Supporting a claim that an explicit anchor adds information also requires an upper bound below zero for candidate minus second-baseline negative log likelihood. Report the mean calibration difference at the final stop and the hit rate for the highest-probability interval or censoring category. States in the linked text come from the same causal path and may already contain context from the original paragraph. This comparison estimates the contribution of the explicit anchor vector. Strict swaps involving the same linked article, identical stops, and mutually exclusive support yield 37 training pairs and 0 dev pairs. This split cannot test whether changing the anchor redirects the model to different evidence. ## Execute and sealed snapshot

Data preparation is complete. First, create a subdirectory using `iirc_linked_pack` and seal six model endpoints into `linked-evidence-model-inputs.tar.gz`. The package contains two split plain-text paths with coordinates, training intervals, and `assay.json`. The held-out annotations are stored in a local preparation directory, while the package only records their hash. Place the package and the `research` Python module from the repo into the L4 environment and unzip them, then execute the following commands in order. [Input Packaging](../../research/semantic_tracking/iirc_linked_pack.py) · [Single Causal Forward Readout](../../research/semantic_tracking/iirc_linked_extract.py) · [Readout Fitting](../../research/semantic_tracking/iirc_linked_fit.py)

```sh
python -m research.semantic_tracking.iirc_linked_extract --inputs inputs --output extraction
python -m research.semantic_tracking.iirc_linked_fit --inputs inputs --features extraction/features.npz --extraction extraction/extraction.json --output fit
```

Extract with a batch limit of 24 paths and 6,144 padded tokens per batch, projecting each of the 191,753 verified reading stops into 128-dimensional FP32 unit vectors. Each path undergoes a single forward pass through the backbone during formal extraction. GPU prefix checks are additionally validated using sampled paths for truncation, right-padding, and suffix replacement. Resuming shards from a previously sealed snapshot within the same execution environment and output directory is supported. Using the rough estimate of 2,419 tokens/s from prior IIRC short paragraph measurements, the current 6,704,880 tokens require approximately 46 minutes for forward and readout. Path lengths are longer, so the first shard's speed has not yet been empirically measured in this experiment. [Previous L4 measurement](../../research/results/iirc-anchor-run/extraction.json)

Upon obtaining the held-out prediction and `fit-manifest.json`, connect `dev/locked-labels.jsonl` and `dev/locked-matched-swaps.jsonl` from the preparation directory on this machine and execute `iirc_linked_score`. The scoring entry will read in the held-out observations only after validating the sealed snapshot hash. [ held-out scoring](../../research/semantic_tracking/iirc_linked_score.py)

## Official held-out results

From 20 validated prefix resumption runs, all 29 fragments were retrieved on a single NVIDIA L4. The entire readout accumulated 6,704,880 tokens and 191,753 causal reading stops, with forward and readout durations totaling 2,820 seconds, averaging 2,378 tokens per second. The peak PyTorch memory retention for fragments was 13.84 GiB. The final resumption segment lasted approximately 18 minutes, encompassing deployment, readout, and matching. Outputs, manifest, and L4 release have been cross-checked.
