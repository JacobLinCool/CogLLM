# Stage 6 · RACE comprehension validation

We trained the readout on OneStopQA open-book human responses, fixed the prediction, and then, within the same Prolific experiment, switched to RACE articles and items. Both corpora presented the full text, stem, and four options simultaneously, sharing 970 reader keys. This experiment validates material not used for readout fitting. The estimated response is which displayed option the reader selected. ## Pre-scoring fixed practices

RACE employs the author-released Prolific TSV alongside the actual displayed text, stem, and option order, totaling 216 passages, 648 questions, and 1,940 responses. Two visible conditions were constructed using the same prompt format as the prior OneStopQA. After deduplication, this yielded 1,851 unique inputs. The model's hidden state was extracted from the final token of the complete prompt. The fixed configuration included Qwen3.5-2B revision, Transformers 5.17.0, and FP32 causal forward pass, with each input processed once. GPU inputs contained only the prompt ID and text, with reader background left empty. Answer keys for correctness evaluation were compared against the fixed original RACE, while the text body used the actual Prolific presentation. The study adheres to RACE's original non-commercial research usage conditions. [Author Data](https://github.com/berzak/onestop-qa/tree/7a058755e1ff0d3f835a67109c669c7e294d4239/human_experiments) · [Original RACE Version](https://huggingface.co/datasets/ehovy/race/tree/2fec9fd81f1dc971569a9b729c43f2f0e6436637) · [Usage Conditions](https://www.cs.cmu.edu/~glai1/data/race/) · [Existing L4 Feature Script](../../research/joint/onestop_features.py)

Reconstruct five-fold linear heads on the local CPU using the original OneStopQA design and saved L4 features, maintaining the same L2 penalty, feature normalization, intercept, and solver. First, verify the reconstructed OneStopQA held-out probability. Display the position priors computed per fold based on human-selected positions. For each condition, the prediction for RACE is the arithmetic mean of the five-fold probabilities. For each experiment's displayed position, output four probabilities: first, seal the snapshot prediction and hash it, then append the human response on the local machine. [Original OneStopQA results](joint-first-run.md#onestopqa-held-out-results) · [Original readout program](../../research/joint/onestop_probe.py)

The primary metric is the negative log-likelihood (NLL) in nats, where lower values indicate a higher probability assigned to the human's actual selected option. The main difference is between passages with text and those with only questions and options. The multi-class Brier score is the sum of squared probability errors across four options, ranging from 0–2. The correct Brier score compares the probability of the correct answer against whether the human answered correctly, ranging from 0–1. Lower values are better for both. Each trial uses equal weighting. 95% confidence intervals are bootstrapped 10,000 times with seed 43, resampling both articles and readers separately, with the product of the two resample counts yielding the weight for each trial. Model weights are fixed. Additionally, descriptive comparisons are conducted by RACE school, high school question banks, and human correct or incorrect responses. ## Execution and Reproducibility

The Colab NVIDIA L4 used a fixed Qwen revision to extract features for 800,720 nonpadding tokens across 3,702 prompts. The forward pass and feature readout took 321.22 seconds in total. Peak reserved GPU memory was 9.29 GiB. All 12 prefix-consistency checks passed. The interval from runtime allocation confirmation to the stop request was 407.19 seconds. Downloaded artifacts passed hash verification, and the L4 was released. Reconstruction of the OneStopQA readout, calculation of RACE probabilities, and scoring against human responses ran on the local CPU.
