# IIRC shared-readout validation

Both the main text anchor and the parallel text matching each have a held-out set. Both experiments use the same Qwen3.5-2B snapshot and fixed projection, but with different original fitting data. The official held-out originally fit 3,354 paths, including 114 paths from the parallel held-out. Therefore, if the same readout is to be used in the interface in the future, weights fitted from 3,240 paths by the parallel experiment must be individually applied to both held-sets. The primary metrics, tolerances, and resampling rules of both experiments remain unchanged. [Official held-out specification](iirc-linked-evidence-protocol.md) · [Parallel text matching specification](iirc-identity-holdout.md)

Fixed-pair experiments fitted to produce `heads.npz`. Replay the 452 causal paths from the official dev split of the original L4 shard using this readout. Align the replay by case and character reading stop, retaining the original unit vector normalization and geometric scaling of the training data. Simultaneously replay the 114 paths from the held-out set, verifying at each reading stop that the difference between the original sealed snapshot prediction and the maximum-probability replay with identical weights does not exceed \(10^{-12}\). Before predicting the sealed snapshot, read only two held-out articles, anchors, reading stops, causal states, and the original sealed snapshot prediction from the fixed-pair experiment. The sealed snapshot simultaneously records weights, fit manifest, original L4 shard manifest, prediction, and execution specification hash. During scoring, use the two held-out annotations, reporting a double held-out pass only if both pass their respective predetermined thresholds.

Use `iirc_linked_identity replay` to obtain causal features for the paired experiment. `iirc_matched_colab prepare` packages the replayed features, training intervals for each example, and the fixed fitting code. `run` fits the packaged data inside a Colab L4 runtime using the prespecified SciPy CPU solver. The runtime receives only the files required for this fit, which runs without reloading Qwen.

`iirc_linked_shared_head forecast` Accept the `--prepared`, `--fit`, `--extraction` of the experiment, the `--original`, `--official-assay` of the raw data, and the released raw L4 `--job`. `iirc_linked_shared_head score` Using the same data, fit weights, and feature manifest, change `--job` to `--predictions` specifying the prediction directory for the sealed snapshot. The `--extraction` of the paired experiment points to the `extraction.json` generated by replay. [Fit Entry](../../research/semantic_tracking/iirc_matched_colab.py) · [sealed snapshot and scoring program](../../research/semantic_tracking/iirc_linked_shared_head.py)

The endpoint of this validation is the interval in which the text evidence, marked post-hoc by the respondent, is fully present, given the source passage, the provided anchor span, and the linked body text. Neither of the held-out sets measured when the original questioner became aware of or resolved the query.
