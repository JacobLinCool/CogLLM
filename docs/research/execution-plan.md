# CogLLM Research Execution Plan

The planning baseline is November 20, 2026. **The lead agent owns execution through delivery. The PI oversees progress, makes experimental design decisions, and interprets the results.** This document records responsibilities, deliverables, acceptance criteria, estimates, and resources. The [training protocol](training-protocol.md) covers the research question and experimental methods. The [mathematical specification](mathematical-formulation.md) defines the equations and model interface.

The study uses existing human observations and published experimental effects. It tests whether one Qwen3.5-2B checkpoint can reproduce response distributions and condition differences with one causal forward pass per article. Where the data contain relevant annotations, it also evaluates response locations and links to source-text spans. The model accepts the article and optional background. A predefined reference reader population applies when background is empty. At the planning baseline, the project had registered 46 empirical studies, aligned three datasets, completed separate baselines, tested effect supervision alongside an external reference diagnostic, and compared trial and effect supervision in shared training across three tasks. Later work extends localized endpoints and held-out validation, with separate measures for individual responses, condition effects, and where they occur. [Literature and data](reading-evidence.md) · [First shared results](joint-first-run.md) · [Joint effect results](joint-effects-run.md)

Prefer public Hugging Face repositories for data and models. Use verified author releases where appropriate. Formal training uses an **NVIDIA L4 on Google Colab**. Local work covers data preparation, source reanalysis, and lightweight program tests. [Source check](reading-evidence.md#hugging-face-source-audit) · [L4 execution and verification](#colab-l4-的執行與驗收)

## Completion Criteria

**CogLLM model.** Use the same sealed Qwen3.5-2B checkpoint and one causal forward pass for each article and specified background to output token- and sentence-level response estimates aligned to the source text. The article is the only required input. Background fields are limited to reader populations or knowledge conditions that existing data can validate. Before formal evaluation, fix the primary observations, splits, statistics, and tolerances. Compare human response distributions and the direction and magnitude of condition effects on held-out materials. Evaluate question onset, linked text, and resolution at the annotation granularity. Claims about updates to the same question require paired trajectories. Retain effects with insufficient precision or testability in the results table. [Human validity criteria](mathematical-formulation.md#真人效度) · [Position-level readouts](mathematical-formulation.md#3-平行讀出反應位置與強度)

**Research papers and expository writing.** In continuously explanatory text, validate where readers experience increased difficulty, its intensity, and their overall response after reading. Explanation order, sentence construction, and coherence cues are primary manipulations. First compare how the model and human responses change across rewrites of the same content. Then use validated response signals to compare rewrites. Evaluate localized difficulty and postreading comprehension at the actual granularity of each human measure. [Responses to scientific exposition and first contrasts](expository-reading-plan.md)

**Gradio text analysis tool.** Authors and editors can paste an article, run analysis, and select positions to inspect the source-text span, endpoint intensity, and scale. Where data support it, they can look up the relevant earlier text and later evidence interval. Use the formally sealed checkpoint and identify the reference readers, validation granularity, and experimental outputs. End-to-end acceptance covers input through original-text annotation, empty background, Unicode offsets, and consistent outputs over shared prefixes when the continuation changes. | Role | Responsibilities and deliverables |
| --- | --- |
| Lead agent | Maintain the plan and progress record, delegate work, integrate outputs, adjudicate source-check disagreements, and track effects with missing data. | Subagents | Independently check literature, label observations, verify data versions and denominators, implement software and analyses, and review results. Assign one accountable agent, delivery location, and set of acceptance criteria to each work package. The lead agent owns the integrated result. |
| PI | Oversee research direction and progress. Determine primary hypotheses, priority reader populations and existing measurement endpoints, effect tolerances, and experimental design. Interpret the model and literature results. The agent provides decision summaries with evidence and tradeoffs. |

Agents handle literature review, effect extraction, labeling, and adjudication. They locate source pages, reproduce numbers, define annotation rules, and encode existing free-text reports. As the workload grows, the lead agent delegates and reviews deliverables. Preserve the original reports and reasons for encoding changes so the evidence and inferences remain auditable.

The PI reviews the work at three points.

1. **Design lock.** The agent submits verified effects, required endpoints, holdout design, and decision tolerances. The PI sets research priorities and approves the formal design. Independent literature, data, and software work can run in parallel.
2. **Holdout lock.** The agent submits available materials and endpoints, evidence coverage, data splits, and analysis rules. The PI reviews the study design and scope of claims. The agent seals the model and scoring rules before evaluating the holdout.
3. **Interpretation.** The agent reports model–human comparisons effect by effect, localization errors, disagreements, and uncertainty. It identifies an existing or prospective contrast that could distinguish competing explanations. The PI determines the scientific interpretation and next research direction.

## Literature Extraction and Signal Selection

The lead agent assigns work by experiment family. Register multiple observations from the same paper as separate entries. Papers sharing human trials, stimuli, or reanalysis belong to one family. One agent extracts evidence from papers and data. A second checks selected effects independently without seeing the first extraction. The lead agent adjudicates with original tables or records and saves discrepancies and rationales. Agreement between extractions checks the process.

Record at least the following for each observation.

- **Source and design.** Paper, experiment, page, table or figure, material and trial family, language, reader population, prior-knowledge measurement time, task, whether readers saw the full text or prefix, and manipulation conditions.
- **Observation and statistics.** Endpoint, scale, stop, linked text, denominator, exclusions, pairing, effect direction and magnitude, and estimation uncertainty. Record published numbers separately from reanalysis.
- **Usable signal.** Original stimuli and trial responses support direct supervision. An effect loss may use original stimuli and a matched aggregate. Record gaps in observation granularity, materials, and precision. Record the role separately as development training, development diagnostic, whole-family holdout, pending retrieval of existing data, or literature context. Identify the applicable readout head. [Weak supervision precedent](https://jmlr.org/papers/v11/mann10a.html)

The data manifest stores source location, access status, release, use terms, hashes, and transformation code. When coding existing free-text reports, agents keep the original response, coding rule, agent role, version, and associated span. Authored and synthetic materials support model-only contrasts and software tests. The human-response field comes from the existing study responses or published data.

The first software checks reproduce two known results. Among 858 structured reader-by-sentence records in the pinned PLABA-EVAL release, 452 select at least one item and 406 expressly report no problem. In the Mandarin free-continuation condition, reanalysis with equal reader weights gives about 77.7% and 11.7% for the two verb types. These examples check adapters and denominators. ### Costs to Measure in the Next Round

1. **Literature review labor.** For the first batch, record initial extraction, independent review, adjudication, and time waiting for data by paper. Plan 25–45 minutes for extraction, 10–20 minutes for review, and 5–15 minutes for adjudication per paper. Across 46 papers this is about 31–61 agent hours. Update from the first measurements.
2. **Full feature extraction.** Sample 30–60 documents with a known length distribution. Measure batch tokens per second, peak memory, and storage for hidden-only, attention-augmented, and logit-augmented features. Deduplicate by article, reader background, visible input, and model version. Within each length bucket, divide input tokens by measured throughput and add loading and writing time. With 300,000 unique tokens, storing four 2,048-dimensional BF16 hidden layers takes about 4.58 GiB plus indices and other features. Reduce attention and vocabulary logits to the required features per batch and cache the exact layers and locations used.
3. **Readouts, effect training, and evaluation.** Record CPU and GPU time, batch size, number of conditions per complete contrast, words and effective tokens, peak memory, and reruns. Comparisons with matched architecture can share frozen features. Refit within-fold standardization and parameters on each training split. If using LoRA, first measure 20–50 actual L4 training steps. A planning scenario with 300,000 processed tokens per epoch, 2–3 epochs, and 1–2 fits totals 600,000–1,800,000 tokens. If measured L4 throughput is 50–300 tokens per second, this takes about 0.6–10 GPU hours, excluding validation, restarts, and extra splits. Set formal batch sizes and sequence lengths using measured L4 peak memory.
4. **Coding and checking existing reports.** On a sample of original records, measure time for text alignment, category coding, independent review, and adjudication separately. Estimate labor from the number of existing reports multiplied by measured per-record time, plus cases that need individual adjudication. For existing structured fields, start with programmatic denominator and missing-label checks and estimate their costs separately from manual coding.
